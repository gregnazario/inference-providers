# ai-providers Phase 3 — Docs Site (GitHub Pages) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the human-facing half of the registry: a static Astro site rendering `dist/catalog.json` — provider guides (auth walkthroughs incl. OAuth, endpoints, API surfaces, quirks, plans), model pages (facts + per-surface offerings with prices and reasoning summaries), generated curl request examples built from the SDK, and a GitHub Pages deploy workflow.

**Architecture:** Plain Astro (no Starlight — every page is data-generated; a docs shell would fight that) in `site/`, added to the pnpm workspace. Pages statically render from `dist/catalog.json` at build time; request examples use `@ai-providers/sdk`'s `authHeaders` + `buildReasoningParam` so the examples can never drift from the data. Deployment: Actions workflow uploading the Pages artifact (inert until the repo is pushed and Pages is enabled). Refinement of spec §7 (which suggested "Astro + Starlight"): plain Astro delivers the same pages with fewer moving parts; Pagefind search is deferred (follow-up).

**Tech Stack:** Astro ^5 (static output), TypeScript, existing workspace packages, GitHub Actions `actions/configure-pages@v5` + `actions/upload-pages-artifact@v3` + `actions/deploy-pages@v4`.

## Global Constraints

- English only; plain commit messages, NO AI attribution trailers; branch `feat/phase3-site` (never commit to main).
- All entity pages render from `dist/catalog.json` — zero hand-written per-provider/model HTML content.
- Astro `base: "/ai-providers/"` (GitHub Pages project URL); internal links via Astro's `import.meta.env.BASE_URL`.
- Site build must run after `pnpm --filter @ai-providers/schema run build`, `pnpm --filter @ai-providers/sdk run build`, and `pnpm emit` (catalog dependency).
- No secrets, no client-side JS beyond none-at-all (pure static HTML + CSS; no framework UI deps).
- Every task's verification is a real `astro build` + grep assertions on generated HTML.

### Task 3: generated curl examples (SDK-driven)

**Files:**
- Create: `site/src/components/CurlExample.astro`
- Modify: `site/src/pages/models/[id].astro` (replace the placeholder comment with the component)

**Interfaces:**
- Consumes: `authHeaders`, `buildReasoningParam`, `ReasoningParamError` from `@ai-providers/sdk`; provider + offering objects.
- Produces: per-offering curl block. Logic:
  1. URL: `endpoint.base_url + endpoint.path`, then `.replaceAll("{model}", offering.wire_id)` — other `{slots}` (region/resource/project) are left visible for the user to substitute.
  2. Headers: `authHeaders(provider, { credential: "<YOUR_API_KEY>" })` rendered as `-H 'Name: value'` lines (sorted for determinism), plus `-H 'Content-Type: application/json'`.
  3. Body per protocol (message "Tell me about the weather." placeholder):
     - `openai-chat`: `{ "model": wire_id, "messages": [...], <fragment?> }`
     - `openai-responses`: `{ "model": wire_id, "input": "...", <fragment?> }`
     - `anthropic-messages`: `{ "model": wire_id, "max_tokens": 1024, "messages": [...], <fragment?> }`
     - `google-generate-content`: `{ "contents": [{ "parts": [{ "text": "..." }] }], <fragment?> }`
     - `bedrock-converse`: `{ "modelId": wire_id, "messages": [...] }` (no current offerings; template for completeness)
  4. Fragment: pick the offering's own default control — if reasoning.effort?.default → `buildReasoningParam(offering, { kind: "effort", effort: default })`; else if budget block → `{ kind: "budget", budget: clampedSample }` where `clampedSample = max(budget.min ?? 512, 2048)` capped at `budget.max` when present; else if toggle → `{ kind: "enabled", enabled: true }`; style `always_on`/`adaptive`/`none` → no fragment. Wrap in try/catch on ReasoningParamError → omit fragment (never fail the build over an example).
  5. JSON.stringify(body, null, 2); render in `<pre><code>` as `curl '<url>' \<newline> -H ... \<newline> -d '...'`.
- Deterministic output (sorted headers, stable JSON key order as constructed).

- [ ] **Step 1: Write the component + wire into models/[id]**
- [ ] **Step 2: Build + verify** — greps: `site/dist/models/anthropic-claude-sonnet-4-6/index.html` contains `curl 'https://api.anthropic.com/v1/messages'`, `-H 'x-api-key: <YOUR_API_KEY>'`, `-H 'anthropic-version: 2023-06-01'`, and `"thinking": { "budget_tokens": 2048 }` (2048 ≥ min 1024); `site/dist/models/google-gemini-2-5-flash/index.html` contains `"thinkingBudget": 2048` nested under generationConfig.thinkingConfig (JSON.stringify of the fragment); `site/dist/models/openai-gpt-5-1/index.html` contains `"reasoning_effort": "none"` on the chat example and `"reasoning": { "effort": "none" }` on the responses example; `site/dist/models/xai-grok-4-5/index.html` example omits xhigh and uses `"reasoning_effort": "high"`; buildReasoningParam `mandatory` offerings (grok) with enabled-true render `"reasoning_effort"` fine.
